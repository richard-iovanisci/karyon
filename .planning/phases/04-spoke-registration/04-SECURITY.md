## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| User shell to registration script | The user runs `scripts/register-spokes-for-flux.sh` with local kubeconfig context. | Local kubeconfig authority; no new secret persistence. |
| Script to spoke apiservers | The script applies RBAC and legacy service-account token Secrets on `k3d-spoke-ml` and `k3d-spoke-apps`. | Cluster-admin credential material generated by Kubernetes. |
| Script to hub apiserver | The script applies `<spoke>-kubeconfig` Secrets imperatively in hub `flux-system`. | Bearer token plus CA data in Kubernetes Secret only. |
| Git repo to Flux controllers | Committed Kustomizations are pulled by Flux source-controller and reconciled by kustomize-controller. | Public-safe YAML; no bearer token content. |
| Flux Kustomization to kubeConfig Secret | `spec.kubeConfig.secretRef.{name,key}` routes reconciliation to the target spoke. | Secret reference metadata, not secret content. |
| Live Bats to kustomize-controller pod | Live tests and script probes exec TLS/auth checks from inside the hub cluster. | Short-lived bearer-token HTTP request over verified TLS. |
| Local Git checkout to origin/main | User commits and pushes declarative files for Flux to reconcile. | Public-safe manifests and docs only. |
| Test output to terminal | Bats and script summaries print diagnostic status. | Must not include bearer token, kubeconfig, or CA material. |
