<objective>
Author the 9 static YAML files that constitute the GitOps tree for hub-spoke reconciliation: 3 hub-side Kustomizations (the index + 2 per-spoke Flux v1 Kustomization CRDs with explicit `spec.kubeConfig`) and 6 spoke seed manifests (2 spokes × 3 files: kustomization index + Namespace + ConfigMap). All declarative; no script execution. These files are committed to Git so Flux's kustomize-controller (running on hub-flux) can reconcile them into the right spokes via the kubeconfigs Plan 04-03 will land.

Purpose: Lock the GitOps source-of-truth before the script runs. The Plan 04-03 script writes these same paths idempotently — but having them committed first means the script's "write canonical YAML" step skips with `info "already done, skipping"` on first invocation. This forces the static contract (spec.kubeConfig present, key: value.yaml explicit, spec.path correct, ConfigMap data.spoke distinct) to match what the script would produce, with code review at commit time.

Output: 9 YAML files totaling ~80 lines (smallest is 4-line namespace.yaml; largest is the ~22-line per-spoke Flux Kustomization). Every file is grep-pinned by Plan 04-01's static bats suite; landing this plan flips the SPOKE-04 + SPOKE-05 + spoke-seed @tests green.
