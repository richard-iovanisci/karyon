**4. Create `docs/wsl-networking.md`** with the following required sections (per PATTERNS.md §docs/wsl-networking.md and RESEARCH.md §Pitfall 5 and §Ref-8):

The document must contain:
- Section: "What Is mirrored Mode and Why It Breaks Docker Custom Networks"
  - Explain: WSL2 mirrored mode mirrors Windows host NICs into WSL2; Docker custom networks (like k8s-net) rely on network isolation that breaks when WSL interfaces share the host address space. References `moby/moby#48201`.
- Section: "v1 Mandate: NAT Mode"
  - Explain: v1 uses `networkingMode=NAT` explicitly. Mirrored is not supported and will cause `scripts/preflight.sh` to exit 1.
- Section: "How Preflight Detects Mirrored Mode"
  - Explain: IP-subnet heuristic — if the default gateway is NOT in the `172.16.0.0/12` Hyper-V NAT range, preflight classifies the network as potentially mirrored. Known false-positive on unusual home networks.
- Section: "Migration: mirrored to NAT (30-second fix)"
  - The exact 5-step procedure:
    1. Edit `%USERPROFILE%\.wslconfig` — set `networkingMode=NAT` (use the template at `config/wslconfig`)
    2. Open PowerShell as normal user and run: `wsl --shutdown`
    3. Wait at least 8 seconds (Hyper-V VM must fully stop)
    4. Open a new WSL terminal
    5. Verify: `ip addr show eth0` — the IP should be in the `172.x.x.x` range
- Section: "Belt-and-Suspenders: Windows Task Scheduler hwclock Hook (Optional)"
  - Document that the `config/hwclock-resume.service` systemd unit covers the Linux-side clock fix, but WSL2's Hyper-V save/restore does not reliably trigger `suspend.target`. Optional Windows-side fix: create a Task Scheduler task triggered by Event ID 107 (Kernel-Power, resume from sleep) that runs: `wsl -u root sh -c "hwclock -s"`. This is more reliable but requires Windows-side setup.
