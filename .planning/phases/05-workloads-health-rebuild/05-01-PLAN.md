<objective>
Create Phase 5's Wave 0 Bats contract before implementation. The tests should
fail closed until scripts/manifests exist, then turn green as Plans 05-02..05-05
land. This protects every locked decision D-01..D-16 and every Phase 5
requirement DEP-01..04, HEALTH-01..07, DESTROY-01..06.

Wave 0 also includes a build-time `kubectl kustomize` verification suite
(`deploy-examples-02-kustomize-build.bats`) that fails CLOSED at planning
verification time if the locked D-04 relative-traversal model
(`../../examples/*`) is not buildable by the pinned toolchain. This removes the
mid-wave execution risk previously documented as an open RESEARCH question.

The live suite is a STATE CHECKER, not a rebuild executor: Plan 05-06 runs
`task rebuild` exactly once (manually); this suite then asserts kubeconfig
contexts, podinfo Available, GPU Job logs, and the elapsed-seconds line written
by `scripts/rebuild.sh` to `/tmp/karyon-rebuild.log`. This prevents the previous
double-rebuild that doubled timing and destroyed clusters between runs.
</objective>

<threat_model>
**ASVS Level:** 1
**Block on:** high

- **T-05-01 Secret leakage via tests:** Static tests must not print real
  `.env` values, kubeconfigs, bearer tokens, or CA private material. Mitigation:
  tests assert public-safe manifest/script literals only and never read `.env`.
- **T-05-02 Accidental destructive live test:** Live state-check tests must
  not initiate destruction themselves. Mitigation: `phase5-02-live.bats` is a
  state checker only — it never invokes `task rebuild`, `task destroy`,
  `scripts/rebuild.sh`, `scripts/destroy.sh`, or `scripts/delete-clusters.sh`.
  It still calls `require_live_destructive()` because the asserted state
  presupposes a destructive run already happened.
- **T-05-03 False-positive tests:** Static tests that only check comments could
  pass without implementation. Mitigation: tests must grep/yq executable files
  and manifests for concrete command/resource literals.
- **T-05-04 Mid-wave traversal failure:** Relative Kustomize references
  (`../../examples/*`) failing at execution would block phase progress.
  Mitigation: dedicated build-time bats suite runs `kubectl kustomize` on both
  spoke trees and exits 0 only if the pinned toolchain accepts the traversal.
</threat_model>
