<objective>
Create Phase 5's Wave 0 Bats contract before implementation. The tests should
parse cleanly under `bats --count` (LOW-1: --count proves parse, not behavior;
real fail-closed comes when these tests run against not-yet-landed scripts in
Plans 05-02..05-05 and turn green as artifacts land). This protects every
locked decision D-01..D-16 and every Phase 5 requirement DEP-01..04,
HEALTH-01..07, DESTROY-01..06.

Wave 0 also includes a build-time `kubectl kustomize` verification suite
(`deploy-examples-02-kustomize-build.bats`) that fails CLOSED at planning
verification time if the locked D-04 relative-traversal model
(`../../examples/*`) is not buildable by the pinned toolchain. This removes the
mid-wave execution risk previously documented as an open RESEARCH question.

The live suite is a STATE CHECKER, not a rebuild executor: Plan 05-06 runs
`task rebuild` exactly once (manually); this suite then asserts kubeconfig
contexts, podinfo Available, GPU Job logs, and the elapsed-seconds line written
by `scripts/rebuild.sh` to `/tmp/karyon-rebuild.log`. This prevents the previous
double-rebuild that doubled timing and destroyed clusters between runs.

This Wave 0 contract was UPDATED in revision round 2 (after cross-AI Codex
review) to pin the following new literals so downstream plans cannot ship
without addressing them:

- HIGH-1 fix: `scripts/rebuild.sh` must contain `kubectl config use-context
  k3d-hub-flux` BEFORE the bootstrap-flux step. `bootstrap-flux.sh` (line 161)
  and `register-spokes-for-flux.sh` (line 632) gate on
  `kubectl config current-context == k3d-hub-flux`. `k3d cluster create`
  switches the current context to the last-created cluster, so without an
  explicit re-pin in `rebuild.sh` between `create-clusters` and `bootstrap-flux`,
  `task rebuild` silently fails the bootstrap step.
- HIGH-2 fix: in-hub DNS probe is pinned to `kubectl exec deploy/source-controller`
  with `getent hosts`. This is read-only (no resource create/delete), satisfying
  the strict health-check read-only contract.
- HIGH-3 fix: `scripts/deploy-examples.sh` must contain a Git visibility gate
  before `flux reconcile`. The static suite asserts the gate's existence and
  remediation text.
- MED-1 fix: prune-lint is comment-aware and scope-limited (matches the actual
  DESTROY-04 requirement; doesn't false-positive on `delete-clusters.sh`'s
  legitimate guardrail comment).
- MED-2 fix: fix-coredns negative greps are narrowed to `k3d cluster
  stop|start|restart spoke-*` so the script can optionally probe spoke DNS post-
  restart to prove the workaround.
- MED-3 fix: deployment-count gate before `kubectl wait --all` matches existing
  `bootstrap-flux.sh` pattern (lines 256-263).
- LOW-1: verify blocks now state explicitly that `bats --count` proves parsing,
  not behavior; fail-closed verification happens when these tests run against
  not-yet-landed scripts and assert their literals.
- LOW-2: negative greps that could match comment lines now filter
  `^[[:space:]]*#` first.
</objective>

<threat_model>
**ASVS Level:** 1
**Block on:** high

- **T-05-01 Secret leakage via tests:** Static tests must not print real
  `.env` values, kubeconfigs, bearer tokens, or CA private material. Mitigation:
  tests assert public-safe manifest/script literals only and never read `.env`.
- **T-05-02 Accidental destructive live test:** Live state-check tests must
  not initiate destruction themselves. Mitigation: `phase5-02-live.bats` is a
  state checker only — it never invokes `task rebuild`, `task destroy`,
  `scripts/rebuild.sh`, `scripts/destroy.sh`, or `scripts/delete-clusters.sh`.
  It still calls `require_live_destructive()` because the asserted state
  presupposes a destructive run already happened.
- **T-05-03 False-positive tests:** Static tests that only check comments could
  pass without implementation. Mitigation: tests must grep/yq executable files
  and manifests for concrete command/resource literals, AND apply
  comment-filtering (`grep -v '^[[:space:]]*#'`) before counting on
  scripts/manifests where comment lines could trigger spurious matches
  (LOW-2 fix).
- **T-05-04 Mid-wave traversal failure:** Relative Kustomize references
  (`../../examples/*`) failing at execution would block phase progress.
  Mitigation: dedicated build-time bats suite runs `kubectl kustomize` on both
  spoke trees and exits 0 only if the pinned toolchain accepts the traversal.
- **T-05-22 Kube-context drift in rebuild chain (HIGH-1):** `bootstrap-flux.sh`
  (line 161) and `register-spokes-for-flux.sh` (line 632) require current
  context `k3d-hub-flux`; `k3d cluster create` switches current context to the
  last-created cluster. Without a re-pin in `scripts/rebuild.sh`, `task rebuild`
  silently breaks even when every script is correct. Mitigation: Wave 0 static
  test asserts the literal `kubectl config use-context k3d-hub-flux` appears in
  `scripts/rebuild.sh` and at a line number strictly less than the
  `bash "${SCRIPT_DIR}/bootstrap-flux.sh"` line number.
- **T-05-23 Unpushed-state Flux skew (HIGH-3):** `flux reconcile kustomization`
  fetches from `origin/main`. If `examples/` or `clusters/spoke-*/kustomization.yaml`
  changes are uncommitted or unpushed, the reconcile silently skips the new
  content and the `kubectl wait` for `podinfo`/`nvidia-smi` times out without a
  clear cause. Mitigation: Wave 0 static test asserts the literal
  `git status --short` AND `HEAD` and `origin/main` comparison appear in
  `scripts/deploy-examples.sh` BEFORE the first `flux reconcile`, and that the
  failure-message remediation text includes `git status` and `git push`.
- **T-05-24 Probe-pod read-only contract collision (HIGH-2):** Creating a
  short-lived probe pod (`kubectl run --rm -it --restart=Never`) is `apply`
  + `delete` and violates the strict read-only `health-check` contract. Using
  `kubectl exec` into an existing Flux deploy is read-only (no create/delete).
  Mitigation: Wave 0 static test asserts the exact literal
  `kubectl --context k3d-hub-flux -n flux-system exec deploy/source-controller
  -- getent hosts k3d-spoke-ml-server-0` in `scripts/health-check.sh` and a
  parallel literal for `k3d-spoke-apps-server-0`.
- **T-05-25 Empty-set kubectl wait pass-through (MED-3):** `kubectl wait
  --all` on zero matching deployments returns 0 immediately. Mitigation: Wave 0
  static tests pin a `wc -l` >= 4 deployment count gate before every
  `kubectl wait --for=condition=Available deploy --all` on Flux controllers in
  `scripts/fix-coredns.sh` and `scripts/health-check.sh`.
</threat_model>
