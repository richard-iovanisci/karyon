Per HIGH-3 from cross-AI Codex review (2026-04-28, revision round 2),
`scripts/deploy-examples.sh` now contains a Git visibility gate at the top
(BEFORE any `flux reconcile`). Flux reconciles from `origin/main`, not the
working tree. If the developer has uncommitted changes in `examples/` or
`clusters/spoke-*/kustomization.yaml`, OR if their local `HEAD` is ahead of
`origin/main`, the `flux reconcile` calls will silently apply the OLD pushed
state and the script's `kubectl wait` for `podinfo`/`nvidia-smi` will time out
with no clear cause. The gate fails fast with explicit `git status` and
`git push` remediation commands.
</objective>

<threat_model>
**ASVS Level:** 1
**Block on:** high

- **T-05-04 Secret leakage in public manifests:** Example manifests must not
  contain tokens, kubeconfigs, passwords, private hostnames, or user-specific
  values. Mitigation: only public podinfo and NVIDIA CUDA image references are
  committed.
- **T-05-05 GitOps drift:** Imperative workload apply to spokes can hide Flux
  failures. Mitigation: `deploy-examples` is GitOps-only and static tests reject
  direct spoke `kubectl apply`.
- **T-05-06 Excessive GPU rerun mutation:** Deleting broad resources could remove
  Phase 4 seed state. Mitigation: rerun deletion is limited to
  `gpu-smoke/nvidia-smi` Job only.
- **T-05-18 Stale source on Job rerun:** Reconciling the Kustomization without
  first refreshing the source can race with source-controller and produce
  immutable-field rejection if the source has not yet pulled the latest commit.
  Mitigation: `flux reconcile source git flux-system --with-source` runs BEFORE
  `flux reconcile kustomization spoke-ml` in `deploy-examples.sh`.
- **T-05-23 Unpushed-state Flux skew (HIGH-3, NEW in revision round 2):** Flux
  reconciles from `origin/main`. If `examples/` or `clusters/spoke-*` changes
  are uncommitted or unpushed, the reconcile silently applies the OLD pushed
  state and the `kubectl wait` for new workloads times out with no clear cause.
  Mitigation: `scripts/deploy-examples.sh` runs a Git visibility gate BEFORE
  any `flux reconcile`. The gate (a) calls `git status --short --
  examples clusters` and exits nonzero if output is non-empty, and (b) compares
  `git rev-parse HEAD` to `git rev-parse origin/main` and exits nonzero if they
  differ. Failure messages include the exact literals `git status` and
  `git push` so the developer sees the remediation immediately.
</threat_model>

  This section runs BEFORE any `flux` invocation. It implements the contract

  1. **Working-tree dirtiness check:**
     ```bash
     dirty="$(git -C "${REPO_ROOT}" status --short -- examples clusters 2>/dev/null || true)"
     if [[ -n "${dirty}" ]]; then
       fail "uncommitted changes detected in paths Flux watches.
          Flux reconciles from origin/main, not the working tree, so the new
          deploy-examples reconcile would silently apply the OLD pushed state
          and \`kubectl wait\` for podinfo/nvidia-smi would time out.
          Inspect:  git status -- examples clusters
          Fix:      commit and push: git add examples clusters && git commit -m '<msg>' && git push
          Then rerun: bash scripts/deploy-examples.sh"
       exit 1
     fi
     ```
  
  2. **Local-vs-remote check:**
     ```bash
     # Fetch origin/main first so the comparison is current.
     if ! git -C "${REPO_ROOT}" fetch origin main >/dev/null 2>&1; then
       fail "could not fetch origin/main before deploy.
          Inspect: git remote -v
          Fix:     verify network access and origin remote, then rerun: bash scripts/deploy-examples.sh"
       exit 1
     fi
     local_head="$(git -C "${REPO_ROOT}" rev-parse HEAD 2>/dev/null || true)"
     remote_head="$(git -C "${REPO_ROOT}" rev-parse origin/main 2>/dev/null || true)"
     if [[ -z "${local_head}" || -z "${remote_head}" ]]; then
       fail "could not resolve HEAD or origin/main before deploy.
          Inspect: git rev-parse HEAD; git rev-parse origin/main
          Fix:     ensure the repo is initialized and origin/main exists, then rerun: bash scripts/deploy-examples.sh"
       exit 1
     fi
     if [[ "${local_head}" != "${remote_head}" ]]; then
       fail "local HEAD (${local_head}) does not match origin/main (${remote_head}).
          Flux reconciles origin/main, not your local branch, so unpushed local
          commits will silently be ignored and the deploy will time out.
          Inspect: git status; git log --oneline origin/main..HEAD
          Fix:     push your local commits: git push
          Then rerun: bash scripts/deploy-examples.sh"
       exit 1
     fi
     pass "git visibility ok: examples/ and clusters/ are clean and HEAD == origin/main"
     ```
