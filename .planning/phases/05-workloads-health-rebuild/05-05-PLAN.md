<objective>
Create destructive UX wrappers and Taskfile entries: `task destroy` and
`task rebuild`. Preserve the existing cache-safe `scripts/delete-clusters.sh`,
add one-prompt confirmation, run the strict rebuild chain, and enforce the
20-minute warm-cache SLO as a hard failure.

Per WARNING #5 from checker round 1, all chain invocations use the
`bash "${SCRIPT_DIR}/<script>.sh"` form (consistent with the bats grep
contract). Per WARNING #7, `rebuild.sh` writes to `/tmp/karyon-rebuild.log`:
- ordered step markers `>>> step destroy`, `>>> step create-clusters`,
  `>>> step bootstrap-flux`, `>>> step register-spokes`,
  `>>> step deploy-examples`, `>>> step health-check`
- a final line `rebuild elapsed seconds: N`
This log is what the live state-checker bats in `phase5-02-live.bats` reads to
verify the chain ran in order and the SLO was met (no double-rebuild needed).
</objective>

<threat_model>
**ASVS Level:** 1
**Block on:** high

- **T-05-12 Accidental destruction:** Destroy/rebuild delete local clusters and
  network. Mitigation: require typed `yes` at the outer task unless an explicit
  approved env var is set by `rebuild`.
- **T-05-13 Cache loss:** Docker prune commands would destroy CUDA build cache
  and break the rebuild SLO. Mitigation: wrappers call `delete-clusters.sh` and
  static tests reject `docker system prune`, `docker builder prune`, and
  `docker image prune`.
- **T-05-14 False SLO pass:** A green health-check after 20 minutes fails the
  project core value. Mitigation: `rebuild.sh` exits nonzero if elapsed seconds
  exceed 1200.
- **T-05-20 Unverifiable SLO claim:** Without a structured log, "elapsed
  seconds <= 1200" and "strict chain ran in order" are not automation-
  checkable. Mitigation: `rebuild.sh` writes ordered step markers and an
  elapsed-seconds line to `/tmp/karyon-rebuild.log`, which Plan 06's state
  checker reads.
</threat_model>

  <action>
Create executable `scripts/rebuild.sh`:

- shebang, `set -euo pipefail`, `SCRIPT_DIR`, `REPO_ROOT`, source
  `preflight-lib.sh`.
- Define `LOG_FILE="/tmp/karyon-rebuild.log"` and truncate it at start
  (`: > "$LOG_FILE"`). Use `tee -a "$LOG_FILE"` to mirror script-progress
  output AND write structured markers to the log so the Plan 06 state-checker
  bats can read it without re-running rebuild.
- Prompt once for typed `yes` unless `KARYON_REBUILD_APPROVED=yes`.
- Record `start_epoch="$(date +%s)"`.
- Run strict chain in this order, emitting an ordered step marker line to
  `$LOG_FILE` immediately before each step (WARNING #7 contract):
  1. `echo ">>> step destroy" | tee -a "$LOG_FILE"`
     `KARYON_DESTROY_APPROVED=yes bash "${SCRIPT_DIR}/destroy.sh"` (WARNING #5)
  2. `echo ">>> step create-clusters" | tee -a "$LOG_FILE"`
     `bash "${SCRIPT_DIR}/create-clusters.sh"`
  3. `echo ">>> step bootstrap-flux" | tee -a "$LOG_FILE"`
     `bash "${SCRIPT_DIR}/bootstrap-flux.sh"`
  4. `echo ">>> step register-spokes" | tee -a "$LOG_FILE"`
     `bash "${SCRIPT_DIR}/register-spokes-for-flux.sh"`
  5. `echo ">>> step deploy-examples" | tee -a "$LOG_FILE"`
     `bash "${SCRIPT_DIR}/deploy-examples.sh"`
  6. `echo ">>> step health-check" | tee -a "$LOG_FILE"`
     `bash "${SCRIPT_DIR}/health-check.sh"`
- After the chain, compute `elapsed=$(( $(date +%s) - start_epoch ))` and
  print/log the line
  `rebuild elapsed seconds: ${elapsed}` via `tee -a "$LOG_FILE"`. This exact
  prefix is what the state-checker bats greps with
  `grep -E '^rebuild elapsed seconds: [0-9]+'`.
- If `elapsed > 1200`, call `fail` with the literal `1200` in the message and
  exit nonzero AFTER printing the elapsed line so the log captures the failed-
  SLO record.
- Do not write timing to a committed file.
- Do not include any docker prune command.
  </action>
