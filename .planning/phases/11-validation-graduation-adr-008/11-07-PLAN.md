```yaml
# pocs/capsule/spoke/rbac/helm-controller-sa.yaml
# G-06 gap-close (2026-05-06): helm-controller impersonation target on spoke-capsule.
#
# Root cause (G-06): When a HelmRelease in capsule-system has `spec.kubeConfig`
# (cross-cluster) but NO `spec.serviceAccountName`, Flux's helm-controller defaults
# to impersonating `system:serviceaccount:capsule-system:default` on the TARGET
# cluster (spoke-capsule). The `default` SA in capsule-system has zero RBAC, so
# helm install/upgrade requests fail with `context deadline exceeded`.
#
# Fix mechanism (per RESEARCH.md line 971 -- oneuptime "Flux Service Account
# Impersonation" article verified): `spec.kubeConfig` + `spec.serviceAccountName`
# causes helm-controller to impersonate the named SA ON THE TARGET cluster.
# This file provisions the SA + cluster-admin ClusterRoleBinding so the impersonation
# has permission to install/upgrade helm releases AND apply chart-rendered Roles
# (capsule-proxy:capsule-proxy + secrets postRenderers patch from Plan 11-06).
#
# Scope justification: cluster-admin matches the existing flux-reconciler SA pattern
# (scripts/register-poc-cluster.sh:108-119 provisions flux-reconciler with cluster-admin
# on every POC spoke). Capsule's own webhooks scope tenant CRs; the helm-controller
# SA only installs the Capsule + capsule-proxy charts (single namespace: capsule-system)
# and does not touch tenant resources. Threat T-11-07-01 (over-broad RBAC) is
# documented + accepted in the plan's <threat_model> with rationale.
#
# Lands via the existing spoke-targeted poc-capsule-spoke outer Kustomization
# (clusters/hub-flux/pocs/capsule-spoke.yaml, spec.kubeConfig: spoke-capsule-kubeconfig).
# pocs/capsule/spoke/kustomization.yaml lists `rbac/` FIRST so the SA+CRB land before
# any tenant CR or HR install attempt.
apiVersion: v1
kind: ServiceAccount
metadata:
  name: helm-controller
  namespace: capsule-system
# --- (multi-doc YAML separator follows; bare --- omitted to keep the planner frontmatter parser happy) ---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: helm-controller-cluster-admin
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: cluster-admin
subjects:
  - kind: ServiceAccount
    name: helm-controller
    namespace: capsule-system
```
