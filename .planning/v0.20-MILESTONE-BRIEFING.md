# v0.20 Milestone Briefing — Capsule POC Demo & RBAC Polish

**Drafted:** 2026-05-18

**Prior milestone:** v0.19 Capsule Multi-Tenancy POC (shipped 2026-05-18)

## Goal

Take the v0.19 Capsule POC from "shipped + technically correct" to **"demo-ready and least-privilege-aligned"** — as quickly as possible against the existing implementation. Land the artifacts and runbook needed to walk a Mixed Eng + Cloud Ops team through the platform-owner / tenant-owner / capsule-proxy story end-to-end, with a strict no-admin posture for every human-exercised role.

**Framing:** Lean milestone. Smallest viable phase count to get a meaningful demo together ASAP. No exploratory side-quests, no architectural revisits, no deferred-backlog catch-up. Existing alpha/bravo tenants and existing Flux reconciliation stay untouched; this milestone is **purely additive**.

## Audience for the resulting demo

Mixed internal team — Engineering + Cloud Ops mix. ~10–15 minute live walkthrough; goal is to leave them able to articulate the platform-owner vs tenant-owner delegation model and the capsule-proxy LIST-filter mechanic.

## In-Scope Requirements (v0.20)

### Demo R1 — Least-privilege tenant role (RBAC narrowing)

A custom `tenant-workload-editor` ClusterRole replaces `admin` for **human-exercised tenant owners** — narrower than k8s' `edit` (no Secret create/edit, no RoleBinding, no ResourceQuota, no LimitRange). The existing Flux SA owner pattern (`clusterRoles: [admin]` for GitOps reconciliation) is **preserved** with talk-track explanation of why automation gets broader scope than humans.

### Demo R2 — Tenant namespace seeding via GlobalTenantResource

A `GlobalTenantResource` CR auto-propagates a hello-world workload into **every tenant namespace** (alpha-app1, tenant-alpha, bravo-app1, tenant-bravo, plus any new tenant the platform-owner provisions live). Resync ≤ 60s so the demo provisioning step shows live propagation.

### Demo R3 — Capsule-proxy two-perspective view

The demo demonstrates LIST/WATCH behavior from two distinct kubeconfigs:

- **Platform-owner** (`capsule-platform-owners` group) — sees all tenants (cluster-scoped Tenant CRs) and all namespaces.
- **Tenant-owner** (via `issue-tenant-kubeconfig.sh`, routes through capsule-proxy on NodePort 30443) — sees only their tenant's namespaces; can `kubectl get`/`logs`/`exec` on the seeded hello workload; is rejected on `kubectl create secret` (R1 boundary); is rejected on cross-tenant access.

### Demo R4 — Polished demo runbook

`docs/poc-capsule-demo.md` captures the 6-act walkthrough (architecture → platform-owner role → provision new tenant live → GlobalTenantResource auto-seed → two perspectives → cleanup), with pre-demo checklist (cluster reachable, fix-dns if needed, kubeconfigs staged) and known-noise notes (e.g. capsule-controller `tls: bad certificate` 1Hz chatter — see Open Question 1).

### Demo R5 — Self-contained delivery path

The demo resources (ClusterRole, GlobalTenantResource) land via a clearly-named delivery mechanism — either GitOps under `pocs/capsule/` or a `task seed-capsule-demo` Taskfile entry. Decision deferred to discuss-phase — see Open Question 3.

## Open Questions (resolve in discuss-phase)

1. **`tls: bad certificate` controller-noise — fix as part of v0.20 R4, document-only in runbook, or defer entirely?** Source identified as node-side TLS probe rejecting capsule's self-signed webhook cert; benign but visually distracting. Fix path (cert-manager + cluster-trusted CA) is non-trivial and touches the D-08-11 contract. Recommended default: document-only in runbook (lean choice).
2. **`tenant-workload-editor` Secrets policy** — read-only (recommended, demonstrates the deliberate boundary), no-access-at-all (strictest), or upstream-`edit`-equivalent (full read+write, less demo-distinct). Affects R1 spec.
3. **Hello-world workload shape** — Pod + Service (recommended; lightweight, visual), ConfigMap-only (fastest, less compelling), or Deployment + Service + ConfigMap (more production-like, slightly heavier). Affects R2 spec.
4. **R5 delivery path** — GitOps via `pocs/capsule/` (production-correct, slower because of push-and-reconcile cycle) or `task seed-capsule-demo` direct apply (fast, self-contained, doesn't model the GitOps story). Affects R5 spec and informs the demo runbook narrative.
5. **New tenant name for the live-provisioning demo moment — "charlie", "demo", "team-foo", something else?** And: provision live during the demo (recommended for the marquee moment) or pre-stage with a `delete + recreate` dance?

## Suggested phase shape (planner guidance — lean default)

To support the "lean / ASAP demo" framing, the suggested decomposition is **2 phases plus close-out**:

1. **Phase A — RBAC narrowing + GlobalTenantResource seed** (R1, R2; possibly R5 if direct-apply path chosen). Wave 0 RED bats scaffolds for the ClusterRole grant matrix and seeded-resource propagation; lands the ClusterRole file + GlobalTenantResource file + delivery mechanism.
2. **Phase B — Two-perspective demo verification + runbook + TLS-noise resolution** (R3, R4, plus Open Question 1 resolution). Verifies platform-owner vs tenant-owner LIST behavior with live kubeconfigs; writes `docs/poc-capsule-demo.md`; addresses or documents the controller TLS chatter per OQ1.
3. **Phase C — v0.20 milestone close + retrospective** (replicates the v0.19 close-out reconciliation pattern at a smaller scale; flips REQ checkboxes, updates STATE.md, runs `/gsd-audit-milestone v0.20`).

The planner may collapse Phase A and B into a single phase if the work feels tight enough. The planner may NOT add a fourth phase for any deferred-backlog item — those stay deferred (see Out of Scope).

## Success criteria (milestone-level)

- Demo runbook lands at `docs/poc-capsule-demo.md` and can be executed end-to-end against a `spoke-capsule` cluster in ≤ 15 minutes by a human reading it cold.
- All human-exercised roles (platform-owner + tenant-workload-editor) demonstrably lack `admin`. `kubectl auth can-i '*' '*'` returns `no` for both.
- `kubectl create secret` is forbidden for tenant-owner under `tenant-workload-editor`.
- Platform-owner sees all tenants; tenant-owner via capsule-proxy sees only their own namespaces. Verified via 2 distinct kubeconfigs.
- `GlobalTenantResource` propagates the hello workload to every tenant namespace within 60s of namespace creation.
- Existing alpha/bravo Flux reconciliation continues to function (no regression).
- v0.18 `task rebuild` SLO < 230s preserved (no regression).
- `/gsd-audit-milestone v0.20` returns `passed`.
